Labels: **OBSERVED** (I ran or read it), **INFERENCE**, **UNVERIFIED**, **NOT TESTED**. Scope: code and tests on this PC (Windows 11 build 26300, two monitors), a security probe, and short web research. Not covered: store, installer, signing (none exist), real games, low-end hardware.

## 2. Findings from the code and tools (prioritized)
| # | Finding | Evidence | Suggested action |
|---|---|---|---|
| 1 | **Layer IPC trusts the `wid` inside the message.** `ipc_handler` in `main.rs` (about line 698) forwards `{wid, msg}` from whatever posts it to `bridge_instance`. Invariant 7 in the security skill says identity must never come from the message. A third-party widget iframe **does** have `window.ipc` and `window.chrome.webview` (OBSERVED: the test widget printed `object` for both and `postMessage` did not throw). | Source read; screenshot of the test widget. | Treat as a real design risk. Add an origin/frame check in the handler or remove the IPC objects from widget frames, and add a regression test. |
| 1b | Forgery attempt: from an isolated third-party widget I posted `storage.set` as `com.plinth.notes`. After a forced state save (applied=false confirmed), Notes storage was still empty. **Impersonation was not demonstrated.** | One run on an isolated state, harmless note value, no real data. The control (a legit write persisting through this exact path) was not run, and only the Notes storage permission was tried. | **INCONCLUSIVE leaning safe.** Do not claim safety; add a proper test (positive control plus forged calls for each permission). |
| 2 | Trust for first-party widgets is decided by the id prefix `com.plinth.` at install (`main.rs` about 1014). Fine while the widgets folder ships with the app; unsafe once downloaded packages exist. | Source; already in your known issues. | Signature- or location-based trust before any store work. |
| 3 | No navigation restriction found on the hub web view (no `with_navigation_handler` in the code). The hub IPC handler also takes any message. | grep of the source. UNVERIFIED that the hub can be navigated away. | Block navigation to anything but the app's own page; test it. |

| 5 | Panic risk: about 320 `unwrap()`/`expect()` calls outside tests (rough count; the pattern excluded lines containing "test"). | grep. | Review the ones on user data and OS calls. |
| 6 | `main.rs` is a 3,000-line monolith. | wc. | Split by area (layer, hub messages, overlays, autotests) when adding the next feature. |

## 3. Research (web, today; thin, single searches)
- **Windows shell fragility.** Microsoft put and later lifted an upgrade block on 24H2 for wallpaper-customization apps such as Wallpaper Engine; Wallpaper Engine 2.6 fixed 24H2 compatibility and web-wallpaper freezes. Microsoft also disclosed shell UI problems on 24H2 and 25H2. Implication (INFERENCE): the desktop layer will keep breaking with Windows updates, so a per-build test matrix and a fast fix path matter. [Neowin](https://www.neowin.net/news/microsoft-updates-fix-for-broken-windows-11-25h2-24h2-crucial-ui-components/)
- **Native video wallpaper.** A hidden feature in some 24H2/25H2 builds accepts MP4/MKV as the wallpaper; not in Stable per the source (UNVERIFIED current state). It would erode "video wallpaper" as a differentiator. [Pureinfotech](https://pureinfotech.com/enable-new-video-wallpaper-windows-11/)
- **Lower memory when paused.** WebView2 has a memory target API (`MemoryUsageTargetLevel` low) and `TrySuspend`/`Resume` (use one approach, not both; low can page memory to disk). Plinth's governor pauses widgets but the fixed WebView2 cost (about 146 MB per Spike B) dominates; this may reduce it while paused. Whether wry exposes the call is UNVERIFIED. [Microsoft docs](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2_19)
- **Code signing.** SignPath Foundation offers free signing for qualifying open-source projects (needs an OSI license and a public repository; individual eligibility not confirmed). Microsoft's Azure Artifact Signing (renamed from Trusted Signing) went GA in January 2026 and is recommended for non-Store distribution; one article says individuals qualify in the US and Canada only. Plinth is Apache-2.0 with a public repo, and this PC's locale is en-CA, so both look plausible (INFERENCE). Check D1 (some store parts proprietary) against SignPath's terms. [Microsoft guidance](https://learn.microsoft.com/windows/apps/package-and-deploy/code-signing-options)
- **Origin checks matter.** Tauri advisories show remote frames reaching IPC and a subdomain-prefix origin check bug; the advice is exact host matches and minimal capabilities. This supports finding 1 and 3. [CVE-2026-42184](https://osv.dev/vulnerability/CVE-2026-42184), [GHSA-57fm-592m-34r7](https://osv.dev/vulnerability/GHSA-57fm-592m-34r7)
- **Rainmeter 5.0** is described as a testing release requiring 64-bit Windows 10 1903 or later; no final date found. Searches on Wallpaper Engine's workshop security and Lively returned nothing usable: **NOT RESEARCHED**.
